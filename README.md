# PMLDL Assignment 1: Deployment

An automated MLOps pipeline with three stages: data engineering, model engineering and deployment.
The pipeline uses the MNIST handwritten digits dataset, a PyTorch CNN and deploys the model as a
FastAPI service and a Streamlit web application in separate Docker containers.
The whole pipeline runs automatically every 5 minutes, orchestrated by Apache Airflow.

## Pipeline overview

```
Stage 1  prepare_data     load raw MNIST files, clean (missing values and outliers), split
Stage 2  train_model      feature engineering, train and evaluate a PyTorch CNN, log to MLflow
Stage 3  deploy_services  build and start the API and the app with Docker Compose
```

Every 5 minutes the Airflow DAG runs these three tasks in order.


## Setup

1. Clone the repository and enter it.

```bash
git clone <repo-url>
cd <repo-name>
```

2. Create a virtual environment with uv and install the dependencies.

```bash
uv venv --python 3.12 .venv
uv pip install -r requirements.txt
source .venv/bin/activate
```

3. Docker must be running on the machine (Docker Desktop or similar).

## Running the pipeline with Airflow

The Airflow home is `services/airflow` (the DAG is in `services/airflow/dags`).

```bash
export AIRFLOW_HOME=$PWD/services/airflow
airflow standalone
```

The first start initializes the database and starts the scheduler, the webserver and the DAG
processor in one process. Open http://localhost:8080 to see the `mnist_pipeline` DAG.
On first start Airflow generates the admin password: it is printed in the server log and
stored in `services/airflow/simple_auth_manager_passwords.json.generated` (user `admin`).
The DAG starts unpaused (`is_paused_upon_creation=False`), so with `catchup=False` it fires
at the next 5 minute boundary and then runs every 5 minutes.
You can also trigger a run manually from the web UI or with:

```bash
airflow dags trigger mnist_pipeline
```

Each run:

1. downloads the raw MNIST files into `data/raw/mnist` if they are not present yet,
2. cleans the data (checks missing values, removes blank images and outliers by pixel sum),
   splits it 90/10 and saves `data/processed/train.npz` and `data/processed/test.npz`,
3. trains the CNN (3 epochs), evaluates it on the test set, logs parameters, metrics and the
   model to MLflow and saves `models/mnist_model.pt`,
4. rebuilds the Docker images and starts the API and the app with `docker compose up -d --build`.

The MLflow tracking database is `mlflow.db` in the repository root. To inspect the runs:

```bash
mlflow ui
```

## Running the stages manually

```bash
python code/datasets/prepare_data.py   # Stage 1
python code/models/train.py            # Stage 2
cd code/deployment && docker compose up -d --build   # Stage 3
```

## API

The API runs at http://localhost:8000. Interactive docs at http://localhost:8000/docs.

- `GET /health` returns the service status.
- `POST /predict` accepts an image file (multipart form field `file`), resizes it to 28x28
  and returns the predicted digit, the confidence and the class probabilities.

Example:

```bash
curl -s -F "file=@photo_of_digit.png" http://localhost:8000/predict
```

## Web application

The Streamlit app runs at http://localhost:8501. It has a file uploader to choose a photo of a
handwritten digit and a Predict button. After pressing the button the app calls the API and shows
the predicted digit, the confidence and the class probabilities.

The app talks to the API over the Docker network (`http://api:8000` inside the containers).
Locally outside Docker the app expects the API at `http://localhost:8000` (override with the
`API_URL` environment variable).

## Stopping the services

```bash
cd code/deployment && docker compose down
```
